1. Environnement Labs et Initialisation

Fichiers et connexion

  • labs-config.conf : Contient les certificats requis pour l'acces au cluster (reseau 10.2, Wifi eduroam ou VM view-linux).
  • labs-config.sh : Script exportant les variables d'environnement. A executer dans chaque session terminal via source labs-config.sh.
  • chmod u+x kubectl : Attribution des permissions d'execution sur le binaire local.
  • kubectl cluster-info : Verifie l'etat du control plane et des services comme CoreDNS.

Gestion des Namespaces

  • Regle de nommage utilisateur : ns-[login].
  • Creation declarative : kubectl apply -f ns-login.yaml.
  • Verification : kubectl get ns -l name=ns-[login].

2. Pods

Definition et architecture

  • La plus petite unite de calcul deployable et gerable dans Kubernetes.
  • Groupe d'un ou plusieurs conteneurs partageant le stockage, la meme adresse IP et le reseau (localhost).
  • Cycle de vie : Pending -> Running -> Succeeded ou Failed.

Commandes d'inspection

# Afficher le format structure
kubectl get pod <pod-name> -n <namespace> -o yaml
kubectl get pod <pod-name> -n <namespace> -o json

# Extraire le nom du conteneur
kubectl get pod <pod-name> -n <namespace> -o jsonpath='{.spec.containers[*].name}'

# Voir les logs et details des evenements
kubectl describe pod <pod-name> -n <namespace>

# Executer un shell ou une commande a l'interieur
kubectl exec -it <pod-name> -n <namespace> -- /bin/sh
kubectl exec -it <pod-name> -n <namespace> -- hostname

# Suppression
kubectl delete pod <pod-name> -n <namespace>

3. ReplicaSets

Fonctionnement

  • Garantit qu'un nombre defini de pods identiques soit actif a tout instant.
  • Associe aux pods uniquement via les labels specifies dans selector.matchLabels.
  • Ne tient pas compte du createur du pod : si un pod orphelin possede les memes labels, il entre dans le pool du ReplicaSet.
  • En cas d'excedent (ex: pods actifs > replicas), le ReplicaSet supprime l'excedent (statut Terminating).
  • En cas de perte (suppression manuelle ou crash), un nouveau pod est genere immediatement.

Commandes cles

# Creation et description
kubectl apply -f rs-nginx.yaml
kubectl describe rs rs-nginx -n <namespace>

# Surveillance en continu
kubectl get pods -n <namespace> -w

# Ajustement du nombre d'instances (Scaling)
kubectl scale rs rs-nginx --replicas=4 -n <namespace>
kubectl scale rs rs-nginx --replicas=2 -n <namespace>

# Suppression du ReplicaSet (supprime egalement ses pods associes)
kubectl delete rs rs-nginx -n <namespace>

4. Deployments

Hierarchie et fonctionnalites

  • Hierarchie : Deployment controle un ReplicaSet, qui controle des Pods.
  • Permet la mise a jour declarative sans coupure (Rolling Update), l'annulation (Rollback), la mise a l'echelle et la mise en pause.

Mise a jour et Rollback

# Appliquer une mise a jour d'image
kubectl set image deployment/dep-nginx nginx=nginx:1.16.1 -n <namespace>

# Verifier l'avancement du deploiement
kubectl rollout status deployment/dep-nginx -n <namespace>

# Visualiser l'historique
kubectl rollout history deployment/dep-nginx -n <namespace>

# Retour arriere en cas d'echec (Rollback)
kubectl rollout undo deployment/dep-nginx --to-revision=1 -n <namespace>

Si une version d'image invalide est fournie (ex: faute de frappe), le nouveau ReplicaSet echoue a demarrer les pods, tandis que l'ancien ReplicaSet maintient les pods fonctionnels.
